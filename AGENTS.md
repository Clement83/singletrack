# AGENTS.md — singletrack

> **Language rule (#1671) — read first.** Everything versioned and published on GitHub is written in **English**: README, `docs/`, this file, `design/README.md`, CONTRIBUTING, SECURITY, CHANGELOG, `.claude/skills/`, **code comments**, developer-facing log and error messages, **commit messages**, release notes and branch names.
> **Exceptions**: `AGENTS.local.md` (not published, French), the app's UI copy (i18n FR/EN in `messages/*.json`, French tone rules below still apply to the French copy), French test data on purpose, quoted French texts (e.g. email drafts to French organisations).
> **New code**: comments in English from now on; a French comment you touch is translated on the way.

Plan mountain-bike rides: a trail map (metropolitan France, centred on the `HOME_LAT`/`HOME_LON` point, centre of France by default), a track editor, dated **outings** and invitation links that guests follow **without an account**.

Operating notes specific to one installation (network, domain, scheduling, ticket tracking) go in `AGENTS.local.md`, ignored by git.

## Stack

Next.js 16 (App Router, strict TypeScript), Tailwind 4 + shadcn/ui conventions, MapLibre GL JS, SQLite + Drizzle (migrations in `src/db/migrations`, applied at start-up), Better Auth (passwordless sign-in: code + link + QR code by email), `next-intl` (FR + EN, no URL prefix), Vitest, ESLint, Node 22. Mountain-bike routing: self-hosted BRouter (`brouter/`). Video conversion: jellyfin-ffmpeg in the image (Intel QSV optional, libx264 fallback).

## Commands (in the container)

```bash
cp .env.example .env                              # then fill in the secrets (BETTER_AUTH_SECRET, INVITE_LINK_KEY…)
docker compose -f docker-compose.yml --profile dev up -d app-dev   # dev: next dev, mounted code, hot reload, port APP_DEV_PORT (3701), throwaway database data/dev.db; then `docker compose stop app-dev`
docker compose -f docker-compose.yml exec app-dev npm test                  # Vitest
docker compose -f docker-compose.yml exec app-dev npm run test:coverage     # coverage + thresholds (vitest.config.ts)
docker compose -f docker-compose.yml exec app-dev npm run lint              # ESLint
docker compose -f docker-compose.yml exec app-dev npx tsc --noEmit          # typecheck
docker compose -f docker-compose.yml exec app-dev npx drizzle-kit generate  # migration after changing src/db/schema.ts
docker compose -f docker-compose.yml exec app-dev npm run tokens:check      # tokens.css up to date + contrasts
docker compose -f docker-compose.yml --profile e2e run --rm e2e             # Playwright e2e (#1523, Chromium in a container, desktop mouse)
./scripts/smoke-docker.sh                         # smoke test of the production image (host, Docker required)
docker compose -f docker-compose.yml run --rm tools npm run elevation:recompute  # #1519: IGN re-elevation + elevation gain recomputed; --dry-run, --force; automatic backup in data/backups
docker compose -f docker-compose.yml run --rm tools npm run sync:osm        # syncs, user:create…: `singletrack-tools` image (same tag as production)
./scripts/get-brouter-segments.sh                 # BRouter segments (≈ 770 MB for France)
```

All code runs in containers. **`docker-compose.yml` = compose file of the maintainer's dev/production instance (production on the published images, `app-dev`, e2e, `tools`); `compose.yml` = distribution compose file, which wins without `-f`: use `docker compose -f docker-compose.yml …` or `COMPOSE_FILE=docker-compose.yml` in `.env`.** Production (`app`, `brouter`) is **never built locally**: it pulls `ghcr.io/clement83/singletrack:${SINGLETRACK_TAG}` (#1670), see "Releases" below. Images build in about a minute (#1673: no `chown -R`, npm and Next.js build caches, generated output excluded by `.dockerignore`). Health: `GET /api/health`.

**Dev (`app-dev`): page reloading in a loop (#1570)** — "[Fast Refresh] rebuilding" with no code change, chunk 404, endless reload. Observed cause: stale Turbopack state in the `next_cache_dev` volume (`/app/.next` of `app-dev`), not the databases in `data/` (SQLite writes measured: no recompilation; a change in `src/` does hot reload). Fix: `docker compose stop app-dev && docker run --rm -v singletrack_next_cache_dev:/n alpine sh -c 'rm -rf /n/* /n/.[!.]*' && docker compose --profile dev up -d app-dev`. `<body>` has `suppressHydrationWarning` (browser extensions that add classes/attributes to it).

## Principles

- **Mobile first** (375 px then desktop), touch targets ≥ 44 px, never an action on hover alone, AA contrast, light and dark themes following the system. Charter and components: [`design/README.md`](design/README.md), visual reference at `/styleguide`, `ui-ux` skill (`.claude/skills/ui-ux/`).
- **Design tokens**: `design/tokens.json` is the single source (`npm run tokens` generates `src/app/styles/tokens.css`). No hard-coded colour. **Default "Singletrack" charter (#1645, id `classique` kept)**: refined neutrals + a single indigo accent, hairlines, Inter 4 with optical axis (`@fontsource-variable/inter/opsz.css`), tight type scale, radii 4/8/12/16 px + `concentric`, layered shadows, glass (72 % + `saturate(180%) blur(20px)`) on floating layers only, `easing` curves (`ease-out`, `ease-spring`) + `press` utility; principles in `design/README.md`, mock-up at `/styleguide` (`foundations.tsx`). **A single charter (#1646)**: Technique nuit, Affiche de trail and Alpin verre are removed (tokens, CSS, fonts); the `chartes` mechanism (#1624: `data-charte`, overrides `chartes: {id: value}`, `extends`, `glass` utility) stays for future charters, details in `design/README.md` § Charters. **Style rules**: 6 px radius (`rounded-md`) for controls (buttons, fields, chips, badges), 12 px (`rounded-2xl`) for cards, panels, sheets and menus, `rounded-full` only for avatars and dots (no more "`rounded-2xl`/`3xl` everywhere"); hairlines rather than heavy shadows; `font-medium`; 18 px icons with a 1.75 stroke; `press` on tap; glass on floating layers only; never hard-code a radius/shadow/font.
- **Multilingual**: no hard-coded UI text, everything goes through `messages/fr.json` and `messages/en.json` (same keys, ICU format). Dates and numbers through `Intl`, `Europe/Paris` time zone. Server errors return codes translated on the client (`errors.*`).
- **Routes**: private under `src/app/(private)/`, public by slug (`/t`, `/s`, `/i`) listed in `src/lib/public-routes.ts` (allow-list, safe by default). Every write route calls `assertUser()`. **`/t/<slug>` is a redirect (#1593)** to `/?t=<slug>` (sheet in the map panel); track not visible ⇒ 404; `/t/<slug>/edit` unchanged; "Share link" gives `/t/<slug>`. Test: `tests/track-redirect.test.ts`.
- **Track map: sheet in the panel (#1586)**: one open track at a time, never a navigation from the map. ## Releases

Production runs **only** on images published by CI (`.github/workflows/images.yml`): `edge` on every push to `main`, `X.Y.Z`, `X.Y` and `latest` on a `vX.Y.Z` tag (amd64 + arm64). Nothing is built on the server.

**Regular ticket** (feature, fix, refactor): commit on `main` locally; **no push, no tag, no production pull**. Test on `app-dev` (and e2e). The change reaches production with the next release.

**Release ticket** (title `[MEP]`; every epic ends with one, depending on its last sub-ticket):

1. Clean working tree; tests, lint, `tsc --noEmit`, `tokens:check` and e2e green on `app-dev`.
2. Pick the version from the commits since the last tag (`git log $(git describe --tags --abbrev=0 2>/dev/null)..HEAD --oneline`): while in `0.x`, a `feat` bumps the minor, only `fix`es bump the patch; a breaking change bumps the minor (major after `1.0.0`).
3. Set `version` in `package.json` and `package-lock.json` (`npm version X.Y.Z --no-git-tag-version` in `app-dev`).
4. Move `## [Unreleased]` in `CHANGELOG.md` to `## [X.Y.Z] - YYYY-MM-DD`, grouped by `Added` / `Changed` / `Fixed` / `Removed`, written for users, in English; leave an empty `## [Unreleased]` above it.
5. Commit `chore(release): vX.Y.Z`, tag `git tag -a vX.Y.Z -m "vX.Y.Z"`, push `main` and the tag (`git push origin main vX.Y.Z`).
6. Wait until the **Images** and **Release** workflows are green for the tag (GitHub API: `/repos/<owner>/singletrack/actions/runs?event=push&branch=vX.Y.Z`). The Release workflow fails if the tag does not match `package.json` or the CHANGELOG section is missing.
7. Deploy the published images (instance-specific steps: `AGENTS.local.md`): pin `SINGLETRACK_TAG=X.Y.Z`, `pull`, `up -d`, healthcheck green, `/api/health` returns the new version.
8. **Rollback**: set `SINGLETRACK_TAG` back to the previous version, `pull`, `up -d`. Migrations only move forward: if the release added one, check that the previous version still starts before rolling back (otherwise restore the database backup taken before the deploy).

Never move or delete a published tag; a bad release is fixed by a new patch release.

## Tests

One test per behaviour, in `tests/`. Coverage measured on `src/lib`, `src/app/api`, `src/proxy.ts`, `src/db`; the thresholds in `vitest.config.ts` (just below the current level) are enforced in CI: raise them when coverage goes up, never lower them to let a change through. Editor (#1522): gestures as pure functions in `src/lib/editor/gestures.ts` (`track-editor.tsx` only calls them); scenarios in `tests/editor-scenarios.test.ts` through the simulator `tests/helpers/editor-sim.ts` (reducer + routing simulated with the real BRouter fixtures `tests/fixtures/brouter/segments.json`, fake screen projection); fixtures (re)recorded and checked against the real BRouter with `docker compose -f docker-compose.yml exec app-dev npx tsx scripts/editor-routing-check.ts [--record]`. Every new editor gesture or bug = a scenario. **Frozen segments (#1686)**: a `line` segment carrying `coords` (import/copy) is *frozen*, a deliberate straight line has none; `moveWaypoint`/`deviateWaypoint` turn frozen neighbours into `route` (recomputed by BRouter); `StoredDoc.frozen?: boolean[]` (optional, legacy documents use a bend heuristic) lets reopening give them their line back; a BRouter failure flags the segment `failed` (red dotted line, retry through the segment menu, warning on publish). **Widened detour (#1641)**: `src/lib/editor/choice.ts` (`planWiden`/`buildWiden`, caps 3 km / 12 points, 8 m tolerance) computes, after a drag, a "new path" that skips the hand-placed points between divergence and rejoin; `state.choice` = new/old pair (actions `widen`, `selectChoice` without history, `commitChoice` = one entry; a following gesture validates the option; undo = before the drag); **desktop UI (#1642)**: `track-editor.tsx` starts the widened computation after a drag (desktop only: routing of the anchors then `buildWiden` → `widen`); both paths are coloured by slope with a halo (selected = thick `primary`, other = thinner `muted`, sources `choice`/`choice-hit-src`, `slope-other`), `ChoiceLabels` chips (difference in km · elevation gain vs the other, click = `selectChoice`), "Keep this path" button + Enter/Escape = `commitChoice`, A = toggle. Mobile: no pair (#1537). e2e: `editor.spec.ts`. Tests: `tests/editor-choice.test.ts` (sim `choice: true`). Guard rails: `api-auth-guard` (every private `/api` route answers 401 without a session), `proxy`, `migrations` (Drizzle schema = migrated database), `api-routes` (statuses, drafts, malformed imports). Before proposing a change: tests, lint and `tsc --noEmit` must pass.
