# AGENTS.md — singletrack

Organiser des sorties VTT : une carte des traces (France métropolitaine, centrée sur le point `HOME_LAT`/`HOME_LON`, centre de la France par défaut), un éditeur de traces, des **sorties** datées et des invitations par lien que les invités suivent **sans compte**.

Les notes d'exploitation propres à une installation (réseau, domaine, planification, suivi des tickets) vont dans `AGENTS.local.md`, ignoré par git.

## Stack

Next.js 16 (App Router, TypeScript strict), Tailwind 4 + conventions shadcn/ui, MapLibre GL JS, SQLite + Drizzle (migrations dans `src/db/migrations`, appliquées au démarrage), Better Auth (connexion sans mot de passe : code + lien + QR code par mail), `next-intl` (FR + EN, sans préfixe d'URL), Vitest, ESLint, Node 22. Routage VTT : BRouter auto-hébergé (`brouter/`).

## Commandes (dans le conteneur)

```bash
cp .env.example .env                              # puis renseigner les secrets (BETTER_AUTH_SECRET, INVITE_LINK_KEY…)
docker compose up -d --build                      # mode dev, rechargement à chaud
docker compose exec app npm test                  # Vitest
docker compose exec app npm run test:coverage     # couverture + seuils (vitest.config.ts)
docker compose -f docker-compose.yml --profile e2e run --rm e2e   # e2e Playwright (#1523, Chromium en conteneur, desktop souris ; -f car compose.yml est celui de distribution)
./scripts/smoke-docker.sh                         # test de fumée de l'image de prod (hôte, Docker requis)
docker compose exec app npm run lint              # ESLint
docker compose exec app npx tsc --noEmit          # typecheck
docker compose exec app npx drizzle-kit generate  # migration après modification de src/db/schema.ts
docker compose exec app npm run tokens:check      # tokens.css à jour + contrastes
docker compose exec app npm run elevation:recompute  # #1519 : recote IGN + recalcule D+ (traces, snapshots, trajets) ; --dry-run, --force ; sauvegarde auto dans data/backups, reprise via data/elevation-recompute.state
./scripts/get-brouter-segments.sh                 # segments BRouter (≈ 770 Mo pour la France)
```

Toute exécution de code se fait dans les conteneurs. Santé : `GET /api/health`.

**Dev : page qui se recharge en boucle (#1570)** — « [Fast Refresh] rebuilding » sans modification de code, chunk 404, rechargement permanent. Cause constatée : état Turbopack périmé dans le volume `next_cache` (`/app/.next`), pas les bases de `data/` (écritures SQLite mesurées : aucune recompilation ; une modification de `src/` recharge bien à chaud). Remède : `docker compose stop app && docker run --rm -v singletrack_next_cache:/n alpine sh -c 'rm -rf /n/* /n/.[!.]*' && docker compose start app`. `<body>` porte `suppressHydrationWarning` (extensions navigateur qui y ajoutent classes/attributs).

## Principes

- **Mobile first** (375 px puis desktop), zones tactiles ≥ 44 px, jamais d'action au seul survol, contraste AA, thèmes clair et sombre selon le système. Charte et composants : [`design/README.md`](design/README.md), référence visuelle sur `/styleguide`, skill `ui-ux` (`.claude/skills/ui-ux/`).
- **Tokens de design** : `design/tokens.json` est la source unique (`npm run tokens` génère `src/app/styles/tokens.css`). Pas de couleur en dur.
- **Multilingue** : aucun texte en dur, tout passe par `messages/fr.json` et `messages/en.json` (mêmes clés, format ICU). Dates et nombres via `Intl`, fuseau `Europe/Paris`. Les erreurs serveur renvoient des codes traduits côté client (`errors.*`).
- **Routes** : privées sous `src/app/(private)/`, publiques par slug (`/t`, `/s`, `/i`) listées dans `src/lib/public-routes.ts` (liste blanche, sûr par défaut). Toute route d'écriture appelle `assertUser()`. **`/t/<slug>` est une redirection (#1593)** vers `/?t=<slug>` (fiche dans le panneau de la carte) ; trace non visible ⇒ 404 ; `/t/<slug>/edit` inchangé ; « Partager le lien » donne `/t/<slug>`. Test : `tests/track-redirect.test.ts`.
- **Carte des traces : fiche dans le panneau (#1586)** : une trace ouverte à la fois, jamais de navigation depuis la carte. Un départ seul ou une ligne de liste (groupe « N traces partent d'ici », « Dans la zone ») ouvre la trace dans le panneau (`src/components/tracks/track-panel.tsx`, données de `GET /api/tracks/<slug>` = `trackSheet`) : stats, sources derrière « ? », sorties prévues ; pied = profil synchronisé avec la carte + « Préparer une sortie », GPX, menu « … ». Tracé coloré par pente sous les départs (`beforeId="clusters"`). Survol d'une ligne (desktop) = aperçu terne (token `map-preview`, géométries `/api/tracks/geometry`). La sélection multiple de #1532/#1533 est retirée (#1584) : un vieux `?sel=` est ignoré puis effacé. Scénario e2e : `e2e/tests/explorer-panel.spec.ts` (après modification du code, `docker compose -f docker-compose.yml --profile e2e restart app-e2e` pour reconstruire).
- **Vue de la carte dans l'URL (#1577)** : `?z=&lat=&lng=` (4 décimales) et `t=<slug>` (trace ouverte) écrits par `replaceState` (seuil `viewChanged`), lus à l'arrivée ; logique pure `src/lib/tracks/map-view.ts`. « Nouvelle trace » passe la vue à `/new` ; « Retour » (`BackToMap`) rouvre l'URL de l'explorateur mémorisée en `sessionStorage`.
- **Visibilité des traces (#1588, epic #1594)** : `track.visibility` = `public` | `friends` | `private` (défaut `public`, sources synchronisées OSM/Geotrek/Utagawa toujours `public`, forcé par `upsertTrack`). Règle d'accès **unique** : `canViewTrack(db, track, userId)` et son jumeau SQL `trackVisibleSql(userId)` (`src/lib/tracks/query.ts`) ; brouillon = auteur seul, `friends` = auteur + copains locaux acceptés (`areFriends`). Préférences de compte `defaultDrawnTrackVisibility` (public) / `defaultImportedTrackVisibility` (private) : `getDefaultTrackVisibility` (`src/lib/user-profile.ts`), `PUT /api/profile`. Test : `tests/track-visibility.test.ts`.
- **Lectures de traces filtrées partout, carte sans session (#1589, epic #1594)** : toute lecture passe par `canViewTrack` / `trackVisibleSql` (liste, géométries, fiche, GPX/KML, choix de trace d'une sortie `createOuting` + `/sorties/nouvelle` + conditions, parent d'une copie) ; invisible ⇒ **404** (jamais 403). Lectures GET ouvertes sans session, ajoutées **explicitement** par `isPublicRead` (`src/lib/public-routes.ts`, testé dans `api-auth-guard`/`proxy`) : `/api/tracks?starts=1` (le reste de `/api/tracks` ⇒ 401), `/api/tracks/geometry`, `GET /api/tracks/<slug>`, `/api/outings/map` (anonyme = sorties `public` seulement). `src/lib/public-read.ts` : `readViewer` (limite 120/min/IP ⇒ 429) et `readCacheHeaders` (`public` anonyme / `private` connecté, `Vary: Cookie`). Matrice : `tests/api-routes.test.ts`.
- **Carte publique, mode visiteur (#1591, epic #1594)** : `/` vit dans `src/app/(explore)/` (layout sans `requireUser` : `getCurrentUser`, zone de messages `private`) et figure dans `PUBLIC_EXACT` ; les autres pages restent sous `(private)/`. Visiteur (`TrackExplorer signedIn=false`) : départs, fiches et sorties **publiques** seulement (filtrage API #1589), GPX/KML ; ni « Mes traces » (`mine` ignoré), ni import, ni création ; « Préparer une sortie », « Modifier une copie », « Voir la sortie » et le bouton « Se connecter » (`SignInButton`, à la place du menu, via `AccountMenu`) passent par `LoginLink`, qui lit l'URL **au clic** (`loginHref`) : `/login?next=/?t=&z=&lat=&lng=`. `safeNext` accepte `/i/<token>` et `/` + paramètres de carte, rien d'autre. Tests : `tests/public-map.test.ts`, `tests/proxy.test.ts`, e2e `e2e/tests/public-map.spec.ts` (sans cookie : `test.use({ extraHTTPHeaders: {} })`).
- **Choisir la visibilité d'une trace (#1590, epic #1594)** : composant unique `src/components/tracks/track-visibility.tsx` (`TrackVisibilityChips`, `TrackVisibilityBadge`, `DefaultTrackVisibility`), textes `trackVisibility.*`. Éditeur (`SaveForm`, prop `initialVisibility` : préférence « dessinées » à la création/copie, valeur actuelle en modification, envoyée à chaque enregistrement), import (présélection « importées » = privée + phrase), menu « … » du panneau (auteur seulement, `PATCH /api/tracks/<slug>` `{visibility}` : 401/403/404/422), badge dans le panneau et « Mes traces » (`sheet.visibility` et `TrackSummary.visibility` ne sont renseignés que pour l'auteur d'une trace modifiable, `null`/absent sinon), préférences dans le menu utilisateur. Valeur inconnue ⇒ 422 `errors.visibilityInvalid` (POST/PUT tracks, import). Sources synchronisées : aucun choix. Tests : `tests/api-routes.test.ts`.
- **Sortie plus visible que sa trace (#1592, epic #1594)** : autorisée (l'organisateur doit voir la trace). `/s`, `/i`, GPX, carte, fiche de découverte et fédération montrent le parcours figé (`trackSnapshot`), jamais la trace : `/s` ne lie `/t/<slug>` que si `canViewTrack` pour le lecteur (sinon `outingPage.trackFrozen`, sans lien), le slug n'est jamais envoyé en fédération. Formulaire de sortie : avertissement `outingVisibility.form.trackStaysPrivate` (`outingWiderThanTrack`, `src/lib/outings/track-exposure.ts`). Test : `tests/api-routes.test.ts`.
- **Sortie ouverte sur la carte (#1596)** : le panneau `outing` de `TrackExplorer` dessine le parcours figé (`trackSnapshot`) comme une trace ouverte (`OpenTrackLayers`, pente + légende + km + profil synchronisé dans le pied, au-dessus de « Voir la fiche »), un seul tracé à la fois. Données à la demande par `GET /api/outings/map/<id>` (`getMapOutingTrack`, `src/lib/outings/map.ts` : géométrie + profil + bbox + fin, **jamais** slug ni id de trace ; mêmes droits que la liste, anonyme = `public`, non visible ⇒ 404 ; lecture publique ajoutée à `isPublicRead`). Hook `useOutingTrack` (`track-panel.tsx`). Tests : `tests/api-routes.test.ts`, e2e `e2e/tests/outing-on-map.spec.ts`.
- **Vue de sortie unique (#1597, epic « Une seule vue de sortie partout »)** : `src/components/outings/outing-view.tsx` (`OutingView`, `role` = `organizer|guest|visitor|anonymous`, `presentation` = `page|panel`). Ordre fixe : en-tête → action principale → RDV + itinéraire → description → parcours → conditions → qui vient → actions secondaires → roulées/photos → commentaires ; aucun appel réseau, les blocs d'action sont passés en slots par la page. `panel` = jusqu'à « Qui vient » seulement, sans carte embarquée (#1596). Branché sur `/s/<slug>` et `/i/<token>` ; fiche de découverte `/sorties/[id]` (rôle `visitor`, « Rejoindre ») et sortie distante `/sorties/distante/[id]` (#1598, `track` nullable ⇒ bloc parcours masqué, `DiscoveryMap` supprimé) y sont branchées ; `/sorties/*` restants restent à migrer. **Panneau de la carte (#1599)** : `presentation="panel"` branché sur `TrackExplorer` ; description, parcours (nom/km/D+) et « Qui vient » (prénoms via `listParticipants` seulement pour un compte rattaché : propriétaire, créateur, invité lié ; sinon compteur) viennent de `GET /api/outings/map/<id>` (`getMapOutingTrack`), aucun appel météo. Démo `/styleguide#sortie`, test `tests/outing-view.test.ts`.
- **Vue de sortie v2, page (#1619, epic #1618)** : `OutingView presentation="page"` (`PageView`) = en-tête (`BackToMap`, partage, menu « … » `OutingMenu` réservé à l'organisateur : inviter, partage/exports, `OutingManager view="manage"` dont « Annuler la sortie » destructive avec confirmation) → carte d'identité (visibilité, « Organisée par X », titre, date·heure, mot de l'organisateur `OrganizerWord` 3 lignes + « Lire plus », RDV + itinéraire, km·D+·niveau, ligne conditions `ConditionsLine` ⇒ ouvre la section, `OutingParticipants inline`/`countOnly`) → action principale (emplacement P2) → parcours (#1621 : `OutingRoute`, aperçu figé 200 px `BaseMap interactive={false}`, profil synchronisé en card, plein écran en `<dialog>` natif avec pan/zoom, Échap ou bouton fermer ; `trackSnapshot` seulement) → sections repliées `OutingSection` (Conditions, Roulées et photos) → actions invité → commentaires (P4). Panneau inchangé. Textes `outingView.*`. **Prochaine étape (#1620)** : encart bouton sous la carte d'identité (slot `nextStep`), contenu par la fonction pure `nextStep()` (`src/lib/outings/next-step.ts`, test `tests/outing-next-step.test.ts`), rendu `NextStepCard`, textes `nextStep.*` ; branché sur `/s` (organisateur) et `/i` (invité), masqué si la sortie est annulée.
- **Qui vient** : bloc `OutingParticipants` sous les conditions sur `/i` et `/s` ; données par `listParticipants` (prénoms seulement, révoqués exclus), démo sur `/styleguide`.
- **Liens secrets** : slugs UUID v4, jetons d'invitation de 256 bits (hash en base, copie chiffrée avec `INVITE_LINK_KEY`, à ne jamais changer), pages `noindex`.
- **Migrations** : ne jamais modifier une migration déjà appliquée ou publiée, en créer une nouvelle (incident `0017`). `scripts/upgrade-test.sh` (CI) migre une base du dernier tag `vX.Y.Z` avec les migrations courantes et refuse toute migration publiée modifiée.
- **Versions (#1485)** : semver dans `package.json` (`config.version`, injectée au build par `next.config.mjs`, affichée dans le menu et `/api/health`) ; `release-please` (`.github/workflows/release.yml`) tient `CHANGELOG.md` et crée tag + GitHub Release à partir des commits conventionnels ; le tag publie les images (#1483). Dependabot, CodeQL, `SECURITY.md`. Détail : `CONTRIBUTING.md`.
- **Config par instance** (#1473) : rien de propre à un serveur dans le code. Point maison `HOME_LAT`/`HOME_LON`, zones `SYNC_ZONES`, sources `DATA_SOURCES` (`sourceEnabled()` dans `src/lib/config.ts` ; incendie et chasse = Var seulement, `fireApplies`/`huntingApplies`). Installation : [`docs/install.md`](docs/install.md). `.env.example` fait foi pour les variables.
- **Sources de données** : OpenStreetMap (ODbL), Geotrek, import GPX/KML, IGN (altitude), Open-Meteo. Respecter licences et attributions ; jamais de scraping.
- **Secrets** : uniquement dans `.env` (hors git), jamais dans le code ni les logs.
- **Fédération (ActivityPub, #1474)** : étude et décisions dans [`docs/federation.md`](docs/federation.md). Code dans `src/lib/federation/` (Fedify 2.4.5 : `index.ts` = singleton sur `globalThis`, acteur, NodeInfo, boîte d'entrée ; `handle.ts` = règle du handle ; `keys.ts` + `crypto.ts` = clés RSA par compte, privée chiffrée avec `FEDERATION_KEY_ENC` (à ne jamais changer) ; `remote-actors.ts` = cache des comptes distants ; `config.ts` = `FEDERATION=on|off`, origine publique tirée de `PUBLIC_URL`/`BETTER_AUTH_URL`, jamais d'un en-tête). **Fédération active par défaut dès que `FEDERATION_KEY_ENC` existe** (#1477 ; `FEDERATION=off` la coupe) : `off` ⇒ `/.well-known/webfinger|nodeinfo`, `/nodeinfo`, `/ap/*` répondent 404 ; `on` : `src/proxy.ts` appelle Fedify **avant** la redirection vers `/login`. File d'envoi et KV Fedify dans `data/federation.db` (réessais exponentiels ~48 h). Fedify doit rester dans `serverExternalPackages` (une seule copie). Handle : `user.handle`, généré à la saisie du prénom (hook Better Auth + rattrapage au démarrage), modifiable une fois (`/api/profile/handle`, menu utilisateur, adresse `handle@domaine` visible si la fédération est active). **Copains entre serveurs (#1475)** : `src/lib/federation/friends.ts` (adresse `paul@serveur`, Follow/Accept/Reject/Undo, `friendship.remote_actor_id`), détail dans `docs/federation.md` §9 ; `listFriends` & co. gèrent locaux et distants sans doublon. **Sorties entre serveurs (#1476)** : `src/lib/federation/outings.ts` (Event + pièce jointe `singletrack:outing`, adressage par visibilité, `Join`/`TentativeAccept`/`Leave` → `Accept`/`Reject`, caches `remote_outing` / `remote_response`), branchements `src/lib/outings/federation-hook.ts`, détail dans `docs/federation.md` §10. **Sécurité et modération (#1477)** : `moderation.ts` (serveurs et comptes bloqués, `LIMITS`, journal des refus, signalements, anti-spam), `inbox-guard.ts` (filtre taille / blocage / débit avant Fedify, dans `src/proxy.ts`), admin = `ADMIN_EMAILS` + `/admin/federation` (`src/lib/admin.ts`), détail `docs/federation.md` §11 ; tout nouvel envoi passe par `safeDeliver` / `send` qui respectent les blocs. Test d'intégration à deux instances : `docker compose exec app npx tsx scripts/federation-two-instances.ts`.

## Tests

Un test par comportement, dans `tests/`. Couverture mesurée sur `src/lib`, `src/app/api`, `src/proxy.ts`, `src/db` ; les seuils de `vitest.config.ts` (juste sous l'état atteint) sont appliqués en CI : les relever quand la couverture monte, jamais les baisser pour faire passer un changement. Éditeur (#1522) : gestes en fonctions pures dans `src/lib/editor/gestures.ts` (`track-editor.tsx` ne fait que les appeler) ; scénarios dans `tests/editor-scenarios.test.ts` via le simulateur `tests/helpers/editor-sim.ts` (reducer + routage simulé par les fixtures BRouter réelles `tests/fixtures/brouter/segments.json`, projection écran fictive) ; fixtures (ré)enregistrées et vérifiées contre le vrai BRouter par `docker compose exec app npx tsx scripts/editor-routing-check.ts [--record]`. Tout nouveau geste ou bug de l'éditeur = un scénario. Garde-fous : `api-auth-guard` (toute route privée de `/api` répond 401 sans session), `proxy`, `migrations` (schéma Drizzle = base migrée), `api-routes` (statuts, brouillons, imports malformés). Avant de proposer un changement : tests, lint et `tsc --noEmit` doivent passer.
